# ADR 0007: 직책 권한 매트릭스 → users 플래그 동기화

- **상태:** 수락됨
- **날짜:** 2026-07-30
- **관련:** ADR 0003 (Gate·팀 스코프는 유지, 기능 플래그 **출처**는 본 ADR)

## 맥락

기능 권한(`setup_view`, Store 재고, GS Brochure, Coach KPI 등)을 People에서 사용자마다 체크박스로 주면 동일 직책 간 불일치·운영 실수가 난다. Coach 팀장만 JOB 기반 동기화 선례가 있다. Setup 공통코드에 직책(`job_title`) 마스터가 이미 있다.

## 결정

- Setup에 **직책 × 권한** 표(`job_title_permissions`)를 둔다.
- 표 저장·직원 `JOB` 변경·Artisan 시, 연동 `users`의 기능 플래그 7개를 표와 같게 **복사(동기화)** 한다.
- **Gate + 팀 스코프 + 목록 쿼리 스코프**(ADR 0003)는 그대로 두고, Gate는 계속 `users` 플래그·헬퍼를 읽는다.
- **`is_admin`(Full Access)** 은 매트릭스에 넣지 않고 사람 단위만 유지한다. 동기화는 admin 계정을 건너뛴다.
- 개인별 예외 권한은 두지 않는다. 해당 7개 플래그는 People에서 수동 편집하지 않는다.
- 기존 플래그로 표를 역추정 시드하지 않는다. 배포 후 표 설정 → 수동 전체 sync.

## 대안

| 대안 | 기각 이유 |
|------|-----------|
| 요청마다 JOB→표 실시간 해석 | Gate·테스트·People 전면 개편, 범위 과다 |
| Spatie Permission | ADR 0003과 동일 — 팀 스코프·기존 플래그와 이중화 |
| `is_admin`도 직책 부여 | 실수로 전체 관리자 양산 위험 |

## 결과

### 긍정

- 직책 표준 권한이 Setup 한곳에서 보인다
- 기존 Gate 소비 코드 변경이 적다

### 부정

- 표와 `users`가 어긋날 수 있어 동기화 트리거·운영 절차가 필수
- 표가 빈 채로 sync하면 비관리자 권한이 일괄 off될 수 있음
